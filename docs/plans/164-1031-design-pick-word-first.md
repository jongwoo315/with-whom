# #164 사람 고르기 화면에서 낱말을 먼저 고르게 하고 저장이 막힌 이유를 보여 준다 — 설계

## 왜

#156 PR 게이트(2026-10-31)에서 jw가 실기기로 사람 고르기 화면을 쓰다가 막혔다. 「새 사람」 이름을 먼저 적었는데 저장
버튼이 안 눌렸다. 별칭 칸이 비어 있었기 때문인데, 화면에는 이유가 나오지 않았다. 낱말 버튼을 먼저 눌러야 한다는 것은
jw가 직접 알아냈다.

- jw 원문: 「ui문제인가 싶기도 하네. '어느 낱말인가' 섹션을 무조건 거쳐야하는 거 였네」
- jw 원문: 「내 생각엔 '어느 낱말인가'를 고른 뒤에 '누구인가'를 선택하는 게 낫지 않을까 하는 생각 (개인적인 의견)」

## 정한 것

| 무엇 | 고른 것 | 이유 |
| --- | --- | --- |
| 순서 | 별칭 칸이 유효해지기 전에는 「누구인가」 칸을 화면에 두지 않는다. 그 자리에 「위에서 낱말을 먼저 고른다」 한 줄만 둔다 | 비활성으로 보여 주면 jw가 겪은 것처럼 누를 수 없는 칸을 먼저 만지게 된다. 안 보이면 순서가 화면에서 드러난다 |
| 「유효하다」의 기준 | 지금 저장 조건과 같은 `PersonDictionary.isValidAliasKey`(비어 있지 않고 공백·쉼표 없음) | 기준이 둘이면 「누구인가는 보이는데 저장은 안 되는」 상태가 다시 생긴다 |
| 막힌 이유 | 저장이 막혔으면 폼 맨 아래에 이유 한 문장을 보인다. 경우는 셋 | 저장 버튼 옆 툴바에는 긴 문장이 안 들어간다 |
| 이유 문장 | 별칭 빈 칸: 「위에서 낱말을 고르거나 별칭을 적어야 저장할 수 있다」 / 별칭에 공백·쉼표: 「별칭에는 띄어쓰기와 쉼표를 넣을 수 없다」 / 새 사람 이름 빈 칸: 「새 사람 이름을 적어야 저장할 수 있다」 | 무엇을 하면 풀리는지가 문장에 들어간다 |
| 이유를 고르는 곳 | Core 함수 `PickRule.blockReason(alias:personName:) -> String?`(저장할 수 있으면 `nil`). 화면은 이 값으로 저장 버튼 상태와 문장을 같이 정한다 | 앱 target에는 테스트가 없다. 규칙을 Core로 빼면 세 경우를 `swift test`로 보인다. 저장 버튼 조건과 문장이 한 함수에서 나와 어긋날 수 없다 |

## 안 고른 것

- 「누구인가」를 비활성(흐리게)으로 보여 주기 — 위 순서 행
- 단계별 화면(낱말 화면 → 사람 화면, NavigationLink) — 시트 하나 안에서 위아래 순서로 충분하다. 화면이 하나 늘면 취소·뒤로가기 경로가 늘어난다
- 별칭 저장·다시 해석 로직(`Importer.pickPerson`) 변경 — 이번 범위가 아니다

## 위험

- 별칭을 고른 뒤 사람을 고르고, 다시 별칭을 지우면 「누구인가」가 사라진다. 고른 사람 값은 남겨 둔다(다시 낱말을 고르면 그대로 보인다)
- 실제 아이폰에서 보기 전에는 문장 길이·위치가 손에 맞는지 모른다. 시뮬레이터 스크린샷으로 대신한다
