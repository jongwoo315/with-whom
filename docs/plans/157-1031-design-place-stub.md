# #157 Moment에 장소 이름·좌표 칸과 빈 지도 탭을 stub으로 넣는다 — 설계

## 왜

앱 설계(§1 데이터 모델, §3 데이터 흐름)는 「언제 어디서 무엇을」의 「어디서」를 사진 GPS로 정한다. 그 일을 할
#158(사진)·#159(장소)·#160(집)·#161(Takeout)이 전부 이 티켓을 선행으로 기다린다. 장소가 들어갈 자리가 지금은
저장 모델에도 화면에도 없다.

이 티켓은 그 자리만 만든다. 값은 비어 있어도 가져오기 → 저장 → 화면 흐름이 끝까지 이어진다. 다음 티켓들은 새 칸을
만드는 대신 「장소 stub을 실제 구현으로 바꾼다」가 된다.

## 정한 것

| 무엇 | 고른 것 | 이유 |
| --- | --- | --- |
| 저장 칸 | `Moment`에 `placeName: String?`, `latitude: Double?`, `longitude: Double?`. 기본값 `nil` | 옵셔널 + 기본값이면 SwiftData가 기존 저장 파일을 자동으로 고쳐 연다(경량 마이그레이션). 역지오코딩이 실패하면 이름 없이 좌표만 남는 경우가 설계 §4에 있어 셋을 따로 둔다 |
| stub 자리 | Core `MomentDraft`에 `place: Place?`(`name: String?`, `latitude`, `longitude`)를 두고 `MomentBuilder.build`가 언제나 `nil`을 넣는다. `Importer`가 그 값을 `Moment`에 옮긴다 | #159가 바꿀 곳이 Core 한 곳으로 정해진다. 가져오기 경로는 이번에 이미 장소 값을 나르게 된다 |
| 다시 가져오기 | 장소가 `nil`인 초안은 저장된 장소를 지우지 않는다 | 다음 티켓들이 장소를 채운 뒤, 장소를 모르는 경로(지금의 캘린더 가져오기)가 그 값을 지우면 안 된다. 지금은 값이 없어 차이가 안 보이지만 규칙은 지금 정한다 |
| 지도 탭 | 네 번째 탭 「장소별」. SwiftUI `Map`에 좌표가 있는 `Moment`마다 표시를 단다. 지금은 0개라 빈 지도 위에 「아직 장소가 있는 일정이 없다」를 띄운다 | 앱 설계 §2 화면 목록의 「장소별 지도(MapKit)」 자리다. 표시를 다는 코드까지 두면 #159가 화면을 안 건드려도 된다 |
| 행 표시 | `MomentRow`에 장소 이름이 있으면 한 줄 더 보인다 | 지금은 안 보인다. 값이 들어오면 바로 보이게 한다 |

## 안 고른 것

- 장소를 별도 `Place` 모델로 두고 `Moment`가 참조하기 — 같은 장소를 여러 일정이 공유하는 일은 #159(좌표 묶기)가 정한다. 지금 모델을 만들면 그 결정을 미리 하게 된다
- 설계 §1의 `출처`(calendar·photo·takeout·manual) 칸 — 출처가 하나뿐인 지금은 쓸 데가 없다. 사진만 있는 날 `Moment`를 만드는 티켓에서 넣는다
- 위치 권한(`NSLocationWhenInUseUsageDescription`) — 지도는 사용자 위치를 쓰지 않는다. 사진 좌표만 쓴다

## 위험

- 저장 모델이 바뀐다. 실기기의 기존 저장 파일(일정 66개, 별칭 6개)이 그대로 열리는지는 시뮬레이터로 대신할 수 없다. 별칭은 다시 만들 수 없는 데이터다
- 위젯도 `App/Models.swift`를 같이 컴파일한다. 위젯 target이 빌드되는지 같이 본다
