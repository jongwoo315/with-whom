# with-whom 설계

친구·연인·가족과 언제 어디서 무엇을 했는지 자동으로 정리하는 iPhone 앱. 사람별·날짜별·장소별로 다시 찾아본다.

## 정한 것

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 첫 버전 사용자 | jw 혼자 (TestFlight 또는 개인 설치) | 직접 써 보고 출시를 정한다 |
| 수익 모델 | 지금 정하지 않는다 | 출시를 정할 때 고른다. 설계는 서버 없이 기기 안에서만 동작한다 |
| 구글 캘린더 | iOS 설정에 구글 계정 추가 → EventKit으로 읽는다 | Calendar API `calendar.readonly`는 Google 앱 심사가 필요한 범위다 |
| 구글 포토 | Takeout JSON을 보조로 읽는다 | 2025-03 이후 Photos API로 전체 사진첩을 못 읽는다. Takeout은 사진마다 시각·좌표 JSON이 있다 |
| 얼굴 묶기 | 다음 버전 | 첫 버전의 「누구와」는 일정 제목과 직접 입력으로 채운다 |
| 통화 기록 | 쓰지 않는다 | iOS가 지난 통화 기록을 앱에 주지 않는다 |
| 제목 해석 방식 | A(규칙) 먼저, 다음에 B(기기 안 LLM) | 끝까지 도는 흐름을 먼저 만들고, 규칙이 놓친 수를 센 뒤 B를 붙일지 정한다 |
| 앱 기술 | Swift + SwiftUI (React Native·Flutter 안 씀) | 입력이 전부 Apple 프레임워크다(EventKit·Contacts·PhotoKit·CoreLocation·Foundation Models). iOS 전용이라 크로스플랫폼의 이득인 Android를 쓰지 않는다 |
| 최소 iOS | 17 (2026-10-29에 26에서 낮춤) | 지금 쓰는 API 중 가장 늦은 것이 iOS 17이다(SwiftData·`@Observable`·`requestFullAccessToEvents`). B는 그 부분만 iOS 26 이상 + Apple Intelligence 기기에서 켠다 |

안 고른 것: 사진 묶음을 하루의 기준으로 삼는 방식. 사진 없이 만난 날(카페에서 얘기만 한 날)이 빠진다.

안 고른 것: React Native·Flutter. 캘린더·연락처·사진은 플러그인(`expo-calendar`·`expo-contacts`·`expo-media-library`, Flutter `photo_manager`)으로 읽을 수 있지만, Foundation Models는 쓸 만한 플러그인이 없어 그 부분은 결국 Swift로 네이티브 모듈을 짜야 한다(2026-10-29 기준, 직접 확인하지 않았다). 실제 아이폰에 설치할 때 Xcode 서명이 필요한 것도 똑같다. Android로 낼 때 다시 본다.

## 1. 구조

- iOS 앱 하나. SwiftUI + SwiftData, 서버 없음. 최소 iOS 17 (위 표 「최소 iOS」)
- 데이터 모델

| 모델 | 필드 | 비고 |
| --- | --- | --- |
| `Moment` | 날짜·시작·끝, 제목 원문, 항목 목록, 장소 이름, 좌표, 출처(calendar·photo·takeout·manual), 원본 id | 한 번의 만남 = 한 `Moment` |
| `Person` | 이름, 별칭, 연락처 id(선택), 관계 라벨(선택) | `Moment`와 다대다 |
| `PhotoRef` | `PHAsset.localIdentifier`(Takeout 전용 사진은 없음), 촬영 시각, 좌표 | 사진은 복사하지 않고 id만 둔다 |

- 처리 순서

```
EventKit 일정 ─┐
PhotoKit 사진 ─┼─> 합치기 ─> 제목 규칙 해석 ─> 역지오코딩 ─> SwiftData
Takeout JSON ─┘                (못 뽑으면 「확인 필요」)
```

- 화면: 사람별 목록, 날짜별 타임라인, 장소별 지도(MapKit), 「확인 필요」 목록
- 이번에 안 하는 것: 얼굴 묶기, 기기 간 동기화, 공유

## 2. 제목 규칙 해석

캘린더 일정 101개 중 장소 칸이 찬 것은 2개, 참석자가 둘 이상인 것은 0개였다. 「누구와·무엇을」은 제목에서 뽑아야 한다.

2026-04-25 ~ 2026-11-25 일정 54개의 제목 꼴 (이름은 가명):

| 꼴 | 개수 | 예 |
| --- | --- | --- |
| 반복 일정 | 23 | `보험료`, `카드 결제일`, 종일 생일 일정 |
| `사람 🤍 - 항목, 항목` | 16 | `가람이 🤍 - 북엇국, 호머, 복분자소주` |
| `사람 + 한 단어` | 6 | `나래 점심`, `다솜 결혼식` |
| 사람만 나열 | 2 | `라온, 마루` |
| 혼자 한 일 | 3 | `헤어컷`, `건강검진` |
| 문장·회식 | 4 | `자기가 바다 보라씨 만나는 날`, `개발팀 회식` |

- 반복 일정은 처음부터 뺀다(`EKEvent.hasRecurrenceRules`). 남는 31개를 해석한다
- 사람은 **사람 사전**으로 찾는다. 이름인지 아닌지를 규칙으로는 알 수 없다
  - 사전은 연락처 이름과 jw가 앱에서 한 번 확인한 이름으로 채운다
  - 붙어 나오는 꼴을 떼고 찾는다: `가람이`·`가람이랑` → `가람`, `보라씨` → `보라`
  - 별칭을 받는다: `자기` → `가람`
- 규칙
  1. ` - `가 있으면 앞은 사람 쪽, 뒤는 `,`로 나눈 항목 목록이다
  2. 토큰 중 사전에 있는 것은 사람이고, 나머지는 항목이다
  3. 사람이 하나도 없으면 「혼자」로 두지 않고 「확인 필요」로 보낸다. `개발팀 회식`이 혼자로 잘못 들어가는 것을 막는다
- 항목이 장소인지 활동인지는 가르지 않는다. 영화 제목·음식·장소가 한 목록에 섞여 있어 규칙으로는 못 나눈다. 항목은 원문 그대로 두고, 장소는 사진 GPS로 정한다. 이 구분이 B가 맡을 몫이다
- 「확인 필요」에서 jw가 사람을 고르면 사전에 들어가고, 같은 이름은 다음부터 자동으로 잡힌다

## 3. 데이터 흐름 — 사진 붙이기와 장소

- 제목 하나가 하루 전체를 적는 일이 많다(08:00 시작 일정에 아침 운동부터 저녁 술자리까지). 그래서 사진을 붙이는 범위는 **일정 시작 2시간 전 ~ 그날 자정**이다. 같은 날 반복 아닌 일정이 둘이면 뒤 일정 시작 시각에서 나눈다
- 사진은 촬영 시각·좌표만 읽는다. 스크린샷은 뺀다(`mediaSubtypes` `.photoScreenshot`)
- 장소 정하기
  1. 한 `Moment`의 사진 좌표를 200m 안쪽끼리 묶는다
  2. 묶음마다 대표 좌표 하나를 역지오코딩한다(`CLGeocoder`)
  3. 결과는 좌표를 소수 셋째 자리(약 100m)로 반올림한 키로 저장하고 다시 묻지 않는다. `CLGeocoder`는 요청이 많으면 Apple이 막는다
- 집: 가장 자주 나오는 좌표 묶음을 첫 실행 때 jw가 「집」으로 고른다. 지도가 집으로 덮이지 않게 한다
- Takeout JSON
  - `photoTakenTime.timestamp`와 `geoData`만 읽는다. `geoData`가 `0, 0`이면 좌표 없음이다
  - 아이폰 사진첩에도 있는 사진은 촬영 시각(초)이 같고 좌표가 50m 안쪽인 것으로 보고 하나만 남긴다
  - 아이폰에 없는 사진은 이미지 없이 시각·좌표만 들어간다. 지도에 점으로만 보인다
- 사진만 있는 날: 반복 아닌 일정이 없는 날에 집 밖에서 찍은 사진이 3장 이상이면 `Moment`를 만들고 「확인 필요」로 보낸다
- 다시 가져오기: 앱을 열 때 마지막으로 가져온 시각 이후만 읽는다. 원본 id(`EKEvent.calendarItemExternalIdentifier`, `PHAsset.localIdentifier`)로 중복을 막는다

## 4. 오류 처리

- 다시 만들 수 없는 데이터는 jw가 손으로 넣은 것뿐이다(사람 사전, 「확인 필요」에서 고른 것, 직접 고친 `Moment`). 나머지는 원본에서 다시 뽑는다
  - 백업 기능은 만들지 않는다. SwiftData 파일은 앱 컨테이너에 있어 아이폰 iCloud 백업에 기본으로 들어간다
- 권한
  - 사진을 「선택한 사진만」 허용하면 그 사진으로만 동작한다. 「사진 N장만 읽는 중」을 띄운다
  - 캘린더 권한을 거부하면 사진만 있는 날 방식으로만 동작한다
- 구글 캘린더가 안 보이면: 첫 실행 때 캘린더 목록을 보여 주고 읽을 것을 jw가 고른다. 구글 캘린더가 없으면 「설정 › 캘린더 › 계정에서 Google 추가」를 안내한다. 회사 캘린더도 여기서 뺀다
- 역지오코딩 실패·제한: 장소 이름을 비우고 좌표만 저장한다. 다음 실행 때 빈 것만 다시 묻는다
- Takeout JSON이 깨졌으면 그 파일만 건너뛰고 「N개 읽음, M개 건너뜀」을 보여 준다
- 원본 일정이 바뀌면(`lastModifiedDate`) 제목을 다시 해석한다. jw가 손으로 고친 칸은 덮어쓰지 않는다. 지워지면 `Moment`는 남기고 「원본 일정 없음」만 붙인다
- iCloud 사진 최적화로 원본이 기기에 없어도 시각·좌표는 읽힌다. 썸네일을 받을 때만 네트워크를 쓴다

## 5. 테스트

- 기기에 붙는 부분(EventKit·PhotoKit·`CLGeocoder`)과 판단하는 부분을 나눈다. 판단하는 부분은 입력과 결과만 있는 함수로 둔다
- 단위 테스트(Swift Testing)
  - 제목 해석: 반복 아닌 일정 31개 꼴을 입력으로, 기대하는 사람·항목을 적어 둔다
  - 사진 붙이기: 촬영 시각·일정 목록을 넣어 어느 사진이 어느 `Moment`에 붙는지 본다. 같은 날 일정 둘인 경우를 넣는다
  - 장소 묶기: 좌표 목록으로 200m 묶음 수를 본다
  - Takeout: JSON 견본 셋(정상, `geoData` `0, 0`, 깨진 파일)
- 기기 연결 부분은 가짜 객체 없이 jw 아이폰에서 직접 돌린다
- 제목 해석 31개가 A의 기준값이다. B를 붙이면 같은 31개로 다시 잰다
- **공개 repo다.** 견본 제목의 사람 이름은 가명으로 바꿔 넣고, 실제 캘린더 데이터는 커밋하지 않는다
